# 活动组织者：预检、分组与当前版本

[教程首页](../README.md)

## 活动前完成

| 项目 | 验收方式 |
| --- | --- |
| 软件 | 每电脑安装 Python/FD/串口驱动，运行 `00_setup.cmd`，打开活动窗口 |
| 下载 | 提前下载仓库 ZIP 与 FD；现场依赖网络下载会拖慢活动 |
| 电源 | 每组 5V 输出实测、极性和接头确认，并观察真实负载压降；12V 适配器只接降压输入 |
| 舵机 | 单颗标签，ID1 上/ID2 下、1Mbps；记录原参数并确认型号/固件匹配 |
| 机械 | 两轴正交，关节与线缆无明显干涉，舵盘不松动，固定螺钉长度合适 |
| 零位 | 每套机械真实直立时，在 V21 窗口保存 ID1/ID2；断开重连后确认读回同一组数，两轴各在 ±48 计数内 |
| IMU | 固定朝向做标记，只读核对前后/侧倾与符号；不能只看灯亮 |
| 记录 | 试做一轮，正常关闭后检查 CSV/JSONL/JSON 保存 |
| 停止 | 确认 Esc 请求停止，两颗均有新鲜卸力反馈；现场停止会失去支撑，要有人扶护 |

组织者先做一次整流程彩排。教程已覆盖步骤，但尚未由完全新手在另一套全新硬件上独立走通；独立 IMU 安装矩阵标定仍需教师协助。

## 建议分为六个小任务

1. **认识器材**：区分 USB 数据线、杜邦线、原装三芯线，找到 COM 口。
2. **舵机编号**：单颗改 ID，断电重启复查，贴标签。
3. **结构搭建**：下 ID2、上 ID1，摆直并检查干涉。
4. **信号接线**：在断电状态接 IMU 四根线、微雪三根线；电源最终由教师复核。
5. **烧录与只读**：使用匹配套件固件，核对角度、反馈、零位与方向。
6. **起身体验**：每组一名操作者、一名扶护者，其他人观察；记录成功/失败原因。

需要现场从零调机械与 IMU 的组别预留额外时间，不把它与“所有人立刻运行同一固件”混在一起。

## 本版技术参数（给教师）

| 项目 | 固定值 |
| --- | --- |
| 固件 | HD1910_RECOVERY_V21（软件已验证，实机起身待验证） |
| 主控 | ESP32-S3 N16R8，外置 CH340 UART USB |
| 桌面串口 | 230400 |
| 舵机 UART | TX17 / RX18，1000000 baud，微雪 A/A |
| IMU | BMI270，I²C 0x68，SDA6 / SCL7，3.3V |
| 机械零位 | 每台机器在真实直立时分别读取 ID1/ID2，保存于 ESP32 NVS |
| 相对角限位 | 上 ±135°、下 ±95° |
| 通常目标步进 | 每轴 26 计数/20ms、领先实测最多192计数 |
| 前倒加速 | FB 正向、Roll>30°且侧倾<0.20rad 时，下轴34计数/20ms |
| 回零 | 9计数/20ms，领先最多24计数，接近零位并稳定后卸力 |
| 供电软件保护 | 4.0～5.5V，活动目标5V |
| 模型/控制 | 50Hz；V21 起身无固定总时限，站稳回零、故障保护或人工停止结束 |
| 编译核心 | Arduino-ESP32 2.0.17；16MB Flash / OPI PSRAM / CDC disabled |

模型网络决定起身增量，状态机处理站稳确认、回零和卸力。当前没有逐轮自动触发，也没有额外“卡住一律加10°”动作。

## 软件版本保留

- `desktop/event_app.py`：保留的活动 UI v1（三步指引完整显示、胶囊按钮、圆角卡片）。
- `desktop/controller.py`：底层控制、通信、记录与状态校验；不作为独立展示界面。
- `firmware/prebuilt/v20/manifest.json`：原机已烧录二进制的 SHA-256、烧录地址与板型。
- 自定义零位/IMU 标定后，为每套硬件另存源码、电脑端和说明，不能只留一个没有标定信息的 `.bin`。

## 验证范围

已完成原机 V20 编译/上传、4200 原模型序列与4200方向适配板上检查、IMU与双舵机卸力反馈检查；桌面数据层/活动UI共29项测试通过。

仿真训练报告与某一轮真机成功不等价，V20前倒加速实际惯性效果还需重复实物试验。原机之外的装配、电源、传感器方向不在这些验证结论里。

本仓库公开内容只包含项目文档、程序、校验清单与公开发行固件。原始设备全闪存/NVS、私人串口记录、电脑绝对路径和登录信息不随活动包分发。
