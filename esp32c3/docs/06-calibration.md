# 6 · 新舵机零位与 IMU 安装方向

[C3 首页](../README.md) · [返回第一次起身](05-first-run.md)

同型号新舵机也可能因舵盘装配相差一齿而有不同直立读数。**ID、关节零位、IMU 水平参考是三件事。**

| 名称 | 含义 | 怎么设 |
| --- | --- | --- |
| ID1 / ID2 | 舵机是谁 | FD 逐颗设置，上 1 下 2 |
| 关节机械零位 | 哪个编码器位置代表实物直立 | 稳定直立时读取，同步修改固件/窗口配置 |
| IMU 水平零点 | 平放底座对应的姿态参考 | 每次上电静止采样；平放时也可点校准 |

“重连 IMU”保留本次水平参考，“校准零点”只改底座姿态参考，都不会写新的舵机编码器零位。

## 6.1 读出属于这台机器的直立编码器

1. 已烧录 C3 V24、接好舵机电源和 A/A UART，关闭 FD 和展示窗口。
2. 底座平放，两轴真实直立。先停止并确认卸力，再轻调关节；不要强行扳动有扭矩的舵机。
3. 双击 `03_read_joint_zero.cmd`，输入 C3 的 COM。
4. 工具验证固件身份，发送 STOP，读取 30 帧新鲜且卸力的位置数据，不驱动关节。
5. 若采样稳定，会显示上 ID1 与下 ID2 的平均读数，保存 `local_joint_zero.json`。这份文件只是测量记录，**不会自动应用**。

原机器的软件值：上 ID1 **337**、下 ID2 **2872**。若真实直立时读数接近这两个值，可继续使用原机包；若明显不一致，按下面修改，不能直接带着错误零位运动。

## 6.2 修改两处，重新编译

`firmware/policy_shadow/joint_limits.h`：

```cpp
constexpr int ZERO[2]={337,2872}; // 顺序：上 ID1、下 ID2
```

`desktop/data.py`：

```python
JOINT_ZEROS = {1:337,2:2872}
```

两处替换成自己测得的直立值，保留 ±135° / ±95° 与原正负方向。按[第 4 章 B](04-flashing.md#build-source)重新编译上传，窗口与固件成套保存。不必仅为调整这两个常数重新训练。

改了源码不能再用原机 `01_flash.cmd`，否则会把固件零位覆盖回 337/2872；脚本会检测并拒绝混用。读零位工具本身不更新二进制、不改模型，也不替你确认机械姿态正确。

本驱动使用有符号多圈位置，不要自己把所有读数对 4096 取模，不要把 0/4095 误当作本程序的硬限位。若舵盘位置、机械干涉或方向不符，由组织者先调整装配再标定。

## 6.3 IMU 不同朝向不能只靠“校准零点”解决

IMU 固定到底座后不再旋转。原机 `calibration_generated.h` 含安装旋转矩阵 `MOUNT_R` 与陀螺仪零偏 `GYRO_BIAS_DPS`，是本机标定，不是所有 BMI270 通用的出厂常数。

先不启动动作，只读检查（站在底座双长槽一侧，面朝机器人）：

| 轻缓改变整个底座 | 预期主要变化 |
| --- | --- |
| 后侧、无长槽边抬高 | Roll 前后角为正，Pitch 接近 0 |
| 恢复平放 | 回到接近 0 |
| 右手侧边缘抬高 | Pitch 左右角为负，Roll 接近 0 |
| 恢复平放 | 再回到接近 0 |

轴互换、方向相反或明显串轴时，先停在只读阶段，组织者重新采集水平/前倾/侧倾/静止数据并生成安装矩阵、零偏，再编译验证。当前下载包不自动生成这些标定；不能承诺任意模块朝向直接刷入就能正确起身。

核对真实行程内无机械干涉、线缆不拉扯、ID/零位/IMU 方向都正确后，再进入扶护测试。
